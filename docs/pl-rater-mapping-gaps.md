Audit: 2026-11-24, Tracey Dittrich's existing Minnesota package. The complete control manifest is `public/mappings/quotecraftz-pl-rater.json`, regenerated by `node scripts/build-pl-rater-mappings.mjs`. It contains mapping metadata, not captured customer values. Secured targets remain local-only.

Installed total after automatic collection migration: **492 reusable bindings**, comprising **487 shared mappings and five local secured mappings**. This replaces the former 688 bindings that repeated driver/vehicle mappings by numbered column. Live verification shows 29 driver-field mapping families and 48 vehicle-field families covering all three current columns, with no unmapped visible controls. Home Property's earlier audit covered 44 mapped visible inputs. Captions and invisible conditional controls are excluded from the red-highlight count. Conditional garage, commute, pool-safety, heat-tank, driver-course and incident-amount controls are included in the manifest for when they become active.

Covered screens: Client Information; Auto General, Vehicles, Additional Interest, Drivers, Incidents and Company Questions; Home General, Property, Additional Interest, Coverage, Additional Information, Loss and Company Questions. The 32 Home optional coverage sections and their available detail controls were inspected individually. Empty inspection rows were cancelled. No quote was rated, bound, purchased or submitted.

Primary client and the first driver column map to the primary contact. Subsequent driver columns map to additional contacts. Driver and vehicle Header/Body keys use `_*` collection bindings, resolved against the visible column identities in page order during scan, capture and fill. Added/removed columns require no additional mapping or Row selection. All columns, including empty controls, establish position so a missing cell does not shift later records. Secured values and scoped notes resolve to the same record positions; saved numbered mappings migrate when read and persist on Save mapping. Vehicles retain distinct records; previous/mailing addresses use customer-address rows 2/3; property data uses property row 1. The audit covers the existing Minnesota package; unvisited products, states, carriers and future layout changes still need review.

## Choices, security and exclusions

### Capture table layout

Drivers are Contact records. First/middle/last name, birthdate, gender, marital status, DL status/state, occupation, education, driver training, good student, telematics, course dates and current-employer tenure use typed Contact destinations. The employer control `rniYearsCurrentEmployer` maps to `contact.iacrm_yearsemployed`; older defaults incorrectly applied this destination to `rniYearsAtOccupation` and now migrate automatically. Occupation tenure stays separate in contact notes pending its own column.

The Intake heading is **Additional timeline data**, not an assertion that the whole driver is unmapped. Identical typed/source-note copies are hidden from this preview; the original notes remain held for CRM history. Different source wording and fields without a safe typed mapping stay visible. Excluded/rated status belongs to Policy Driver (the Contact rating-status column is deprecated); filing and assigned-vehicle inputs still need conditional transforms/relationship resolution. These are representation gaps, not evidence that a Driver is a different entity from Contact.

Education has a complete explicit choice crosswalk for all ten observed PL Rater options and maps only to Contact `educationcode`; the redundant education-note target is removed from both existing default mappings and new imports. Different wording alone is not an education gap. Live checked examples: High School → High School Diploma (`298400002`), Bachelor's Degree → Bachelors (`298400006`), Community or Junior College → Associates Degree (`298400005`). Remaining choices are Less than High School → No High School Diploma, GED → High School Diploma, Some College → Some College - No Degree, Masters Degree → Masters, Ph. D. → PhD, and the corresponding Medical/Law Degree choices. The generator includes their explicit CRM option values; regression coverage checks the entire crosswalk and concrete primary/additional-contact routing.

Residence type (`select:cmbResType`) maps only to Property `iacrm_residencetype`, with no duplicate property-note target. All eight observed source options have explicit choice bindings: Single Family Dwelling → Dwelling (`298400000`), Apartment (`298400001`), Condo → Condominium (`298400002`), Townhouse (`298400003`), Rowhouse (`298400004`), Co-op (`298400005`), Mobile Home (`298400006`), Other (`298400007`). The installed extension receives these reviewed defaults for missing bindings while retaining explicit agent choice overrides. The share manifest includes the same crosswalk. Live acceptance confirmed Res Type = Dwelling in the typed Properties table and no residence-type column in the property fallback table. This field is distinct from occupancy, ownership, usage and the more detailed one-family/duplex Dwelling Type field.

The Intake preview displays field names as column headers with their values beneath, one contact, vehicle or property per row. Native form controls use the same record grouping as captured data-service tables. Scoped notes and masked secured identifiers also use horizontal field-header tables. Headers stay visible during vertical scrolling; wider tables scroll horizontally. Presentation grouping does not modify held capture data or CRM destinations, and multiple targets still display a source field only once. The installed extension was checked on the live PL Rater driver page with three separate contact rows and three masked license rows.

Non Mapped Timeline Entries now combines numbered note targets by record type: one Vehicles table, one Properties table and one Drivers / contacts table, each with a Record column and a separate row for each slot. Available vehicle year/make/model, contact name or property address identifies the row. Fields from different source pages share headers; missing answers stay blank and differing answers remain visible. Existing grids for other risk types retain their rows. Prior-policy contexts remain identified within the corresponding destination table. The same table builder formats CRM timeline-note HTML, while each CRM note still receives only the fields routed to that individual record.

The native-control harvester also accepts concrete related-contact note targets (`note:contact2` through `note:contact39`). Previously, these resolved collection targets lost their note routing even though the primary contact's fallback worked. Regression coverage now checks primary and additional-driver fallback routing together.

### Capture-label correction

The mapping editor and harvester previously used separate caption resolvers. The driver grid's first caption, `Date of Birth / Age`, was consequently reused for gender, licensing, occupation and note entries; the name grid similarly reused First Name for surnames. Capture now shares the editor's PL Rater control-label resolver. Re-ingestion replaces stale captions for the same control/target on the same site while retaining other held pages. Never fill controls are excluded from new capture rows. A live driver re-ingestion verified distinct First Name, Last Name, Date of Birth, Gender, License Status, Excluded Driver and Years at Occupation labels, including scoped notes and secured identifiers.

Explicit choice translations: Work → Commute; Leasing Company → Lessor; all ten education levels; Undergraduate → College Student; hip-roof variants → Hip; In-Ground → In Ground. Original source choices are also retained in scoped notes alongside coarser CRM classifications. Unsupported indoor-pool/construction variants remain recoverable. Placeholders are not answers.

Billing/payment and carrier agent-identity controls are Never fill. Derived driver age and years licensed are Never fill because DOB and licensing date are separate inputs. Prospect/Client does not control CRM lead qualification. SSN/license numbers use secured pass-through, never notes or repository data.

Import the manifest through the site's mapping import in extension Settings. Import retains other sites and local secured mappings. The nine original secured client/driver bindings migrate to five reusable local mappings; driver license and SSN each cover the complete current driver collection. Vehicle-note writes require a successfully loaded matching vehicle and fail visibly instead of falling back to an account/property.

PL Rater's existing package has Protective Devices enabled without individual devices selected. It can show a required-information dialog on navigation. Do not fabricate device answers to bypass it; inspect the controls and return to the existing quote without rating it.
